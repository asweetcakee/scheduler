# Frontend Decisions (Deferred)

### 1. Note column display strategy (table)
Q: Как показывать длинные заметки (до 2000 символов) в таблице клиентов?
- Status: Deferred

Current decision: показываем truncate (обрезанный текст) в ячейке таблицы
Why: временное решение, чтобы не ломать вёрстку таблицы; полноценный просмотр не реализован
When: когда заметки реальных пользователей начнут регулярно обрезаться и это станет проблемой

Options considered:
- Модалка/попап с полным текстом по клику на заметку (рекомендованный вариант)
- Expandable row — строка разворачивается вниз по клику, показывая полный текст
- Просто убрать текст заметки из таблицы, показывать иконку/бейдж "Есть заметка", текст доступен только в форме редактирования

### 2. Auto-grow textarea for Note field (без ручного resize)
Q: Должно ли поле "Заметка" само растягиваться по высоте контента, без участия пользователя?
- Status: Deferred

Current decision: используется `resize-y` — пользователь растягивает вручную
Why: `resize-y` — простое и достаточное решение для MVP
When: если понадобится более "premium" ощущение формы (авто-рост требует библиотеки `react-textarea-autosize` или ручного JS на `onInput`)

### 3. Mobile table layout (cards instead of scroll)
Q: Как таблица клиентов должна вести себя на мобильных экранах?
- Status: Deferred

Current decision: используется `overflow-x-auto` (горизонтальный скролл таблицы)
Why: минимум кода, решает проблему "не ломается на мобиле"; мобильный UX не оптимизирован
When: если реальные пользователи будут часто заходить с телефона и жаловаться на горизонтальный скролл

Options considered:
- Скрывать `thead`/таблицу на мобильных (`hidden md:table`), рендерить вместо неё карточки (`md:hidden`) с той же информацией

### 4. Phone input masking library
Q: Стоит ли заменить самописную логику маски телефона на готовую библиотеку?
- Status: Deferred

Current decision: самописное решение через сравнение длины строки в `onChange`
Why: работает корректно для текущего простого кейса (один формат номера, курсор всегда в конце)
When: если появятся другие поля с масками (даты, карты и т.п.), или потребуется поддержка редактирования номера в произвольном месте строки (курсор не в конце)

Options considered:
- `react-input-mask`
- `imask` / `react-imask`

### 5. Modal accessibility (a11y)
Q: Нужны ли ARIA-атрибуты и клавиатурное управление для `Modal`?
- Status: Deferred

Current decision: закрытие модалки работает только по клику на оверлей
Why: не критично для внутреннего инструмента / раннего этапа проекта
When: перед публичным релизом продукта, если важна доступность (screen readers, keyboard-only навигация)

Options considered:
- `role='dialog'` и `aria-modal='true'` на внешнем div модалки
- Закрытие по `Escape` через `useEffect` с `keydown`-листенером
